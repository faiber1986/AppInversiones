- (decision) AD-2 Local-first, cero infraestructura. Alternativa descartada: VPS o contenedor con Postgres gestionado. Por que: la carga de trabajo es un operador ejecutando analisis por lotes sobre kilobytes de datos curados a mano; ningun requisito del brief necesita un servidor, y los datos fiscales de clientes no salen de la maquina. Costo de revertir a 6 meses: BAJO-MODERADO (1-2 dias de empaquetado, no reescritura) precisamente porque AD-1 mantiene el nucleo puro y AD-3 mantiene el estado en archivos.
- (decision) AD-3 Sin motor de base de datos. Dos niveles de almacenamiento: (a) texto YAML versionado en git para config tributaria, catalogo de vehiculos y tarifas de broker; (b) snapshots Parquet inmutables en disco para el cache de datos de mercado. Alternativa descartada: Postgres o SQLite. Por que: el brief EXIGE parametros versionados por fecha de vigencia con historia auditable, y git ya es exactamente ese mecanismo. Una base de datos exigiria construir a mano tablas temporales/de auditoria para replicar lo que git da gratis, mas un demonio, mas respaldos. Costo de revertir a 6 meses: BAJO, un puerto de repositorio aisla las lecturas.
- (decision) AD-1 Paradigma hexagonal (puertos y adaptadores) con nucleo funcional puro. El nucleo (motor de friccion, motor fiscal, motor de escenarios) importa solo stdlib, decimal y pydantic. Tiene PROHIBIDO importar streamlit, anthropic, httpx, requests o cualquier libreria de E/S. Los adaptadores dependen del nucleo; el nucleo nunca depende de un adaptador. Alternativa descartada: capas clasicas con acceso a datos desde el dominio. Por que: la seccion 5 exige un motor puro y la 2.6 exige tests con casos calculados a mano, ambos imposibles si el dominio hace E/S. Costo de revertir: ALTO, es la decision estructural que sostiene todas las demas; por eso se fija aqui.
- (decision) AD-4 Todo valor monetario es un objeto Money(Decimal, Moneda) explicito. Nunca float, nunca Decimal desnudo cruzando un limite de modulo. Alternativa descartada: float con redondeo al presentar. Por que: aritmetica binaria de punto flotante produce centavos distintos segun el orden de operaciones, y el brief exige que cada cifra se pueda descomponer y reproducir; ademas el sistema mezcla COP y USD en cada calculo, y una suma silenciosa entre monedas es el error mas caro posible aqui. Costo de revertir: ALTO, atraviesa todas las firmas.
- (decision) AD-5 El evento gravable anual se declara por vehiculo, no se deriva de si distribuye. Campo evento_ingreso_anual con valores dividendo | rendimiento_financiero | ninguno_hasta_realizar. Corrige el defecto de la seccion 5.4 del brief: CDT, TES y FIC generan rendimientos financieros gravables anualmente sin que exista dividendo.
- (decision) AD-6 Cada vehiculo declara la convencion de su retorno esperado: bruto_de_ter o neto_de_ter. El motor solo resta TER cuando la convencion es bruto_de_ter. Previene el doble conteo del TER, que ya viene descontado del NAV de un ETF.
- (decision) AD-7 La configuracion tributaria se indexa por (escenario, vigencia_desde) y el cargador FALLA RUIDOSAMENTE ante cualquier parametro marcado TODO o ausente. Nunca hay valor por defecto numerico. Alternativa descartada: defaults razonables con advertencia. Por que: el brief seccion 12 lo dice literal, un numero inventado en una herramienta financiera es peor que un campo vacio.
- (decision) AD-8 El motor no devuelve escalares: devuelve un libro de asientos append-only de entradas tipadas (anio, concepto, monto, formula, inputs). Los totales se derivan sumando el libro, nunca se calculan aparte. Implementa la trazabilidad de la seccion 2.2: toda cifra del output se descompone hasta su formula. Previene que dos modulos reporten un total distinto para el mismo concepto.
- (decision) AD-9 El adaptador LLM es de solo salida y esta guardado numericamente. Recibe un JSON de resultados ya calculados, nunca una peticion de calculo. Un guard deterministico extrae todo token numerico de la prosa generada y falla el render si alguno no aparece en el JSON de origen. Convierte la prohibicion de la seccion 8 en un test ejecutable en vez de una instruccion de prompt.
- (decision) AD-10 Los disclaimers legales los emite el pipeline de render, no las plantillas ni el LLM. Todo artefacto de salida pasa por un unico renderer que adjunta el bloque legal y la fecha de vigencia de la config usada. Previene que una nueva ruta de salida se publique sin disclaimers, que el brief seccion 9 marca como bloqueante.
- (decision) AD-11 Los datos de mercado se leen tras un puerto y se persisten como snapshots inmutables direccionados por contenido. Cada corrida registra el id del snapshot que uso. Permite reproducir un memorando de hace seis meses con los datos de entonces y cumple la seccion 2.5 (cambiar de proveedor sin tocar logica de negocio).
- (decision) AD-12 Generacion de PDF por Chromium headless via playwright, con HTML como unico formato intermedio. Alternativa descartada: WeasyPrint. Por que: WeasyPrint exige Pango, cairo y GDK-PixBuf de GTK+ instalados aparte en Windows, con fallos de instalacion reportados en Windows 11 hasta 2025-2026 (issues Kozea/WeasyPrint 2480 y 863). El operador ya tiene playwright funcionando. Costo de revertir: BAJO, el HTML intermedio es el contrato y el motor de PDF es intercambiable.
- (decision) AD-13 Monolito de un solo proceso, un solo paquete Python. Alternativa descartada: separar motor y UI en servicios. Por que: no hay segundo consumidor, no hay limite de escalado y no hay equipo que separar; servicios anadirian serializacion, versionado de contrato y un modo de fallo nuevo a cambio de nada. La seccion 3 del brief deja multi-tenant, autenticacion y facturacion explicitamente fuera de alcance.
- (decision) AD-14 La interfaz es una app Streamlit local que se lanza en localhost y no se expone a red. Alternativa descartada: CLI mas reporte HTML estatico. Por que: la seccion 3 pide ajustar supuestos interactivamente, y Streamlit da esa interactividad en Python puro sin servidor web propio, sin JavaScript y sin costo. Alternativa descartada 2: FastAPI mas frontend. Por que: introduce dos lenguajes y un contrato HTTP para un unico usuario local. Costo de revertir a 6 meses: BAJO, la UI es un adaptador delgado sobre el nucleo por AD-1; el CLI puede coexistir.
- (decision) AD-15 Interprete fijado a Python 3.12 via .python-version, gestionado con uv. Alternativa descartada: Python 3.14.3, el default del operador. Por que: 3.12 tiene la cobertura de wheels mas amplia y en una herramienta financiera la ruleta de dependencias no compensa la novedad. uv ya tiene 3.12.12 descargado, asi que no cuesta nada. Costo de revertir: TRIVIAL, editar .python-version y re-lockear.
